# ADR-0025: Formalize the ADR practice, distributed and self-practiced

**Status:** Accepted
**Date:** 2026-08-19

## Context

`design-solution` already shipped `assets/decision.template.md` — structurally
an Architecture Decision Record (`Context`/`Decision`/`Alternatives
considered`/`Consequences`/`Revisit when`) — but underspecified in three
ways: no fixed storage location (the skill said only to use it "for a durable
cross-cutting decision that must outlive the design document," never where),
no numbering convention, and no append-only rule. Its own header fields
(`**Owners:**`, plural) didn't even match what this repository's own
`docs/adr/` practice actually uses (`**Status:**`/`**Date:**` only, no owner
field at all). This repository has practiced ADRs on itself since
`0001-work-lifecycle-invariant.md`, informally, entirely from author memory —
no `docs/adr/README.md` recorded the convention anywhere, for CoDev's own
contributors or for anyone reading it as an example.

The request that surfaced this: add ADRs as a first-class CoDev concept,
because the practice is worth having, not just something this repository
happens to do internally. Two questions shaped the scope, both resolved by
direct instruction: rename `decision` to `ADR` throughout, matching the
terminology-lock discipline ADR-0023 already established (industry-standard
term over an in-house one); and keep it skill-guided rather than adding CLI
scaffolding, consistent with how every other planning artifact in CoDev
(brief, design, delivery plan) is already agent-written directly from a
template, not generated by a command.

## Decision

### Rename and reconcile: `decision.template.md` -> `assets/adr.template.md`

`design-solution/assets/decision.template.md` is renamed
`assets/adr.template.md`. Its header changes `**Owners:**` (plural, unique to
this template) to `**Owner:**` (singular), matching `brief.template.md` and
`design.template.md`'s existing field name. `**Related design:**` gains an
explicit `[link or Not applicable]` placeholder, matching every other
optional-field convention in these templates. The template itself now carries
a `> **How to use this file.**` guidance block (the same pattern
`design-doc.md`'s own guidance blocks use) naming the storage path, the
numbering rule, and the append-only rule directly at the point an agent would
otherwise have to guess them.

### Storage and numbering, made explicit in `design-solution/SKILL.md`

An ADR is saved at `docs/adr/NNNN-slug.md`, `NNNN` the next four-digit,
zero-padded sequence number after the highest one already present in
`docs/adr/` (starting at `0001` if the directory does not exist yet). This is
exactly the scheme this repository's own `docs/adr/` already used --
formalizing it, not inventing a new one.

### Append-only, with an explicit `Superseded` path

Once `Accepted`, an ADR's `Context` and `Decision` are never edited to
reflect new information -- a later reversal writes a new ADR and sets the
old one's Status to `Superseded by ADR-NNNN`, linking forward. This matches
every ADR in this directory's own practice to date (0001-0024 have never been
retroactively edited) and the pattern `design-doc-conventions.md`'s Appendix
A ("Superseded decisions") already names as the right shape for traceability.

### CoDev practices this on itself: `docs/adr/README.md`

A new `docs/adr/README.md`, non-bundled (repository-specific, like
`docs/product-map.md`), documents this repository's own convention explicitly
for the first time -- filename shape, header fields, the three `Status`
values, the append-only rule, and that numbers are never reused even for an
abandoned proposal.

### Not built: CLI scaffolding

A `codev adr new` command was considered and set aside, at the user's
direction: no other planning artifact (brief, design, delivery plan) is
CLI-generated in CoDev today -- each is written directly from its template by
the agent following skill instructions, with numbering/dating handled the
same way. Adding CLI scaffolding for ADRs alone would be a new, inconsistent
pattern for one artifact type. Not ruled out permanently, just not part of
this change.

## Consequences

- `scripts/validate-development-workflow.py`'s `EXPECTED_SKILLS` registry
  updated: `design-solution`'s required asset is now `assets/adr.template.md`.
- `.codev/for-ai/ai-agent-guidelines.md`'s Artifact authority table gains an
  `ADR` row, between `Design / API document` and `Delivery plan / tracker`.
- `docs/product-map.md`'s Terminology table gains an ADR row (superseding
  "decision"/`decision.template.md`), and a new "Resolved and implemented
  (ADR-0025)" note in Directions and open questions.
- No `ROUND_SCHEMA_VERSION` or CLI change -- this is a skill-asset rename and
  a documentation addition, not a change to any tracked state.
- Root dogfood copies need the same `codev update` resync every prior bundle
  change in this working tree already needs; not run as part of this ADR,
  same as ADR-0023/0024.
